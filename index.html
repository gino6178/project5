01 缺口：兩條現有路線各缺一半

機器人換一個空間時，理想上面對的應該是「同一套佈置，只是換了房間」——沙發仍然對著電視、餐椅仍然圍著餐桌。要做到這件事，必須同時滿足兩個互相衝突的要求：語意一致（相對的、對尺度敏感）與物理可行（絕對的、由邊界決定）。現有的兩條路線各自只解一半。

路線語意保留物理可行缺什麼
生成式合成（ATISS / PhyScene）無機制分布內佳與來源房間無關；房型條件綁在資料集分布上
仿射映射Smotif 1.0009.7% 出界家具是剛體，目標邊界不是等比副本
GRT（本文）Smotif 1.000Col_obj 0.207–0.518可達率仍不如 PhyScene（§5）
仿射的失效不在關係層面而在物理層面——它的 motif 保留是完美的 1.000。這修正了 project4 早期版本的動機敘事。

為什麼不能靠後處理補

多步的測試期最佳化緩慢且易陷局部極值；硬性吸附會把物件推離生成流形，破壞剛保住的關係結構並引入二次碰撞。更根本的是，它讓系統不再端到端：模型被訓練去優化一個目標，部署時卻套用另一個。

03 量測效度：一個被撤下的指標

我們先量錯了，然後撤下它

最初以一個與類別無關的 2D 足跡重疊率量測碰撞。把同一個指標套用到真實 3D-FRONT 佈局，得到 0.629——高於 PhyScene 在任何房型下的數值。一個讓真實房間比生成結果更「糟」的指標，量的不是碰撞。

原因是它把合理的貼靠算成碰撞：餐椅塞在桌下、床頭櫃靠著床。改用 PhyScene 自己的有向 3D IoU 後，真實佈局為 0.400，數值方具可比性。

這件事同時是本文的一個論據：如果連量測碰撞都需要知道哪些關係允許貼靠，那麼建模時更不可能用一個與類別無關的重疊懲罰。這直接導向 §4 的設計決策——「什麼算違規」必須由設計圖定義，而且要用學的。

  • 像素↔公尺映射：60 間真實房間上為 20.43 ± 0.16 px/m，一致。
  • 出界率：對真實佈局的合理性已查核。
  • 已撤下：與類別無關的 2D 碰撞率，不再出現於任何表。

04 架構：Graph-Refinement Transformer

不用 DiT，不是為了換一個，而是這個任務有天然初始化（來源佈局的仿射轉置）。project4 自己的消融顯示：拿掉 informative prior，Srel 掉 0.054、碰撞翻倍——大部分的工作是初始化做的，從噪聲跑 50 步 ODE 是浪費。

圖同時扮演三個角色

  • 定義何謂正確：PairGapPredictor 從邊特徵與兩個物件的條件預測「該有的間距」與容忍度，由真實佈局中觀察到的間距以 Gaussian NLL 監督，所以不會塌縮成「什麼都允許」。評分時預測被 detach，逼佈局向學到的間距靠攏，而非讓預測遷就佈局。
  • 傳遞資訊：邊特徵同時調變注意力 logits 與 訊息（graph transformer，而非只加純量偏置）。
  • 每塊重讀：違規以 token 特徵進網路，不是進損失。網路因此學會如何修正，而不是沿固定能量梯度走——後者只有局部視野，繞不過凹角。

驗證：模型自己學到了貼靠

餐桌–餐椅（有邊）→ 期望間距 −0.37 m（該重疊）；桌–無關物件（無邊）→ +1.75 m（該分開）。沒有任何一張「哪些關係允許貼靠」的規則表——手寫規則只是把建模搬進規則裡，那會變成工程論文。

可走性也是可微的

PhyScene 的可走性算得好，是因為它光柵化——連通性在網格上很自然。但硬性 flood fill 不可微，只能評分已完成的佈局，無法塑造佈局。walkable.py 把同一個量做成可微：柔性佔據 → 自由空間 → 以 3×3 max-pool 逐格擴散的鬆弛 flood fill → blocked ratio。它同時當作 token 特徵與損失項。

贏在哪

碰撞率：五個房型全勝，而且不是小勝。GRT 在四個房型上（0.207–0.237）不只低於 PhyScene（0.429–0.542），也低於真實 3D-FRONT 佈局的 0.400。這是 PhyScene 明確以引導最佳化的軸線，值得注意。狹長走廊差距最小（0.518 對 0.556）——那也是兩邊都最吃力的房型。

狹長走廊的出界率減半以上：0.255 對 0.556。PhyScene 在該房型有超過半數物件落在樓面外；GRT 因為從來源佈局的仿射轉置出發、再對邊界做交叉注意，房型偏離分布時不會失去參照。

語意保留：PhyScene 沒有這個機制。GRT 的 Smotif = 1.000、Srel = 0.935 ± 0.030（uniform，N=36）。PhyScene 生成的場景與來源房間無關，這一欄不是分數高低而是能力缺口。

輸在哪（如實報告）

可達率：五個房型輸四個（走廊 0.767 對 0.870，L 形 0.829 對 0.940）。PhyScene 直接在光柵網格上以引導最佳化可達性，而 GRT 優化的是 blocked 面積——不是同一個量。run 4 正在處理（§6）。

凹角房型的出界率：L 形 0.270 對 0.226、T 形 0.252 對 0.214。仿射轉置在凹角處把物件推出邊界，六個精修塊沒有完全拉回。碰撞已經修好、出界還沒有，因為兩者的壓力來源不同：前者來自學習式間距這個目標，後者只透過違規特徵間接進入。run 4 正在處理（§6）。

對 project4 失敗判準的檢核

判準是「無後處理的可行性 ≥ project4 加了 Πθ 之後的水準，尤其在非凸房型（2.83%）」。GRT 在 hard／L 形上的 R_col 為 2.09%，uniform 為 2.98%——達標，且不需要任何測試期投影。Srelkept 0.935 未退步，速度為單次前向。

06 訓練紀錄

run 1

類別無關能量 捨棄

以與類別無關的重疊懲罰訓練，val_recon 上升 8 倍。可行性與重建互相打架——因為那個能量會懲罰掉正要保留的貼靠結構。這個失敗直接催生了 PairGapPredictor。

run 2

恆等塌縮 捨棄

指標與仿射warp 完全一致（Srel 0.934、Smotif 1.000、R_col 4.69% 對 4.88%）。量測相對輸入的位移：0.048 m——模型什麼都沒做。

根因在資料，不在調參。 RetargetPairs 以反向形變生成訓練對：真實房間 → 形變邊界 → 用那個形變佈局當參考。所以模型的起點（仿射轉置）天生就已接近 GT，重建梯度很弱，恆等是最省力解。

run 3

提高可行性壓力 塌縮已解 已評測

修正訊號必須來自可行性項，因此 w_terminal 0.4→2.0、w_walk 1.0→2.0、w_monotone 0.2→0.5。這一步先前不能做——類別無關的能量會撞上重建；換成學習式間距（由真實佈局監督）之後，兩個目標才一致。

結果：位移 0.048 → 0.342 m，恆等塌縮解除。60 epochs 收斂（term 0.049、rel 0.008、walk 0.062）。同時每個 epoch 記錄位移量，讓塌縮在前幾個 epoch 就現形。最佳檢查點在 epoch 43。對照結果見 §5。

run 4

可達率與凹角出界率 訓練中

run 3 輸的兩個軸同一個成因：包容性與可達性只以特徵進入模型，從未進入目標；而可走性損失優化的是 blocked 面積，PhyScene 報的卻是每物件的可達率——一個佈局可以幾乎沒有不可達的地板，同時把某個物件圍死。

新增兩個終端項：boundary_outside（有向框最差角點對最近邊界內法向的外露公尺數，對應 R_out 的「任一像素出界」，取代保守的外接圓半徑）與 object_reachability（每物件的鬆弛可達性）。兩者同時也成為違規特徵（N_VIOL 7→9）。

下一輪之前先驗證，抓到兩個鬆弛 bug

一個鬆弛量只有在「跟著它所替代的指標一起動」時才有用。check_terms.py 拿答案已知的佈局去量，在燒掉 60 epochs 之前抓到兩個錯誤：

錯誤症狀成因修法
柔性 gate 隨距離衰減真實佈局讀 0.39（指標 0.94）完全自由的格子仍只給 sigmoid(6)=0.9975，連乘 72 輪 → 0.835；free=0.9 → 0.55straight-through：傳播用硬 gate，梯度走柔性
量測環與阻擋物同時膨脹幾乎所有物件讀不可達環正好落在 free≈0.5，恰是硬 gate 的切點照 PhyScene 定義分離：阻擋物膨脹半個機器人寬，查詢遮罩再往外膨脹
修完後讀數跨格數穩定（q=2.5 時 G=32／48／64 各讀 0.861／0.857／0.867），這才確認控制變數是公尺寬度而非格子數。定案 G=48、sharp=20、query=1.5：真實佈局 0.81、擠進半個房間 0.27、全部堆在中心 0.00。

踩過的坑（已記錄，避免重蹈）

.gitignore 未錨定的 data/ 連函式庫的 reroom/data/ 一起排除，全新 clone 直接 ImportError。已錨定為 /data/。

07 待辦與失敗判準

失敗判準先寫下來。與 project4 在相同協定下比較，GRT 必須做到：

  • 無後處理的可行性 ≥ project4 加了 Πθ 之後的水準，尤其在非凸房型（project4 Table 2：2.83%）

若 GRT 只能打平「flow + 外掛投影」，就誠實報成 negative result——它會反過來說明分階段是正確的分解，而非妥協。兩種結果都可寫，都不值得誇大。目前狀態：三項判準皆達標（§5 末），但對 PhyScene 的可達率仍落後，該項如實列為未解。
